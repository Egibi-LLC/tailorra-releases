Provider-agnostic cancellation registry for AI operations.

Every long-running AI command (polish, extract, suggest, style generation/tweak/attachment) accepts an optional operation_id from the frontend. When supplied, the command registers a cancellation channel under that id before doing work. A separate cancel_ai_operation Tauri command signals the channel, which the running command observes via tokio::select!.

Provider-specific cleanup (kill the CLI child process, drop the HTTP future to abort the request) happens inside each provider’s command function — this module only owns the channel plumbing.

Structs§

AiOpRegistry
Process-wide registry of in-flight cancellable AI operations. Lives as Tauri-managed state. Each entry maps an operation id (chosen by the frontend, typically a uuid) to a oneshot sender — sending or dropping it signals the watching task. The sender is tagged with a registration generation so a guard can tell its own entry apart from a newer one that reused the id.
CancelGuard
RAII guard returned by AiOpRegistry::register. While alive, holds the receiver for the registered op’s cancellation signal. Dropping it (typically on function return) automatically removes the sender it registered, but only if the entry still carries the guard’s own generation: if the frontend reused the id for a newer op, that op’s sender is left in place so it stays cancellable.
