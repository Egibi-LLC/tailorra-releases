Module claude_cli 

Source
Expand description

Claude Code CLI provider — invokes the local claude binary instead of hitting api.anthropic.com. Lets users on a Claude Max/Pro plan route tailor’s AI operations through their existing subscription instead of paying separately for API tokens.

The CLI is shelled out non-interactively with:

  • -p : print response, no interactive UI
  • --output-format json : structured response on stdout
  • --tools "" : disable all tools (we want pure completion)
  • --permission-mode dontAsk: auto-deny anything that would prompt
  • --system-prompt <text> : fully replace the default system prompt

Long inputs (master corpus, rendered HTML for polish) are piped via stdin to avoid command-line length limits on Windows. The CLI’s JSON output wraps the model’s text in a result field — we extract and return that.

Multi-modal flows (style mimic from PDF / image upload) are NOT implemented here yet; those continue to use the API path. The CLI’s attachment story is uncertain, and it’s an occasional setup-time operation where falling back to API is acceptable.

Structs§

CliCallEndEvent
Emitted after the CLI returns (or errors). The frontend looks up the matching start entry by id and merges these completion fields into it (response on success, error on failure, plus elapsed time).
CliCallStartEvent
Emitted before the CLI is invoked so the frontend log can show the call immediately as “running” — the user sees what’s being asked without waiting for the model to finish. id is a monotonic counter the frontend uses to match this with the corresponding end event.
CliOptions
Optional per-call configuration coming from the frontend’s CLI settings panel (model override, etc.). Each AI command accepts this alongside its other inputs and threads it down to the CLI invocation.
