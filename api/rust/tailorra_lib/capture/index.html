Local HTTP server that the browser extension talks to.

Binds 127.0.0.1:CAPTURE_PORT and exposes authenticated endpoints in two directions:

  • POST /capture (extension → app): takes a JSON payload from the extension (URL, page title, raw HTML, optional source-site identifier). The handler prefers the extension’s pre-extracted text, falling back to converting the HTML via html2text, then either emits a Tauri listing-captured event with the result or, while no webview listener is registered yet, buffers it in the CaptureBridge until the frontend drains it. The frontend’s CaptureService listens for that event, inserts a job_listings row through the SQL plugin, and surfaces a toast; AI extraction is not triggered automatically, the user runs it later from the listing.

  • GET /autofill/package + GET /autofill/package/files (app → extension): serve the application package the user last prepared from a tailored version (contact profile plus the resume rendered to PDF/DOCX), so the extension can fill an employer’s application form. The renderer owns the data and the render pipeline, so the package is pushed here via the set_autofill_package command and held in memory only; nothing is persisted and a fresh app start has no package until the user prepares one again.

Auth: Authorization: Bearer <token> against a token stored in the OS keychain. Generated on demand from the Browser Capture settings page; kept in memory in the AppState so each request doesn’t pay a keychain round-trip.

CORS: wildcard allow-origin/methods/headers via CorsLayer::new() because browser extensions run from chrome-extension:// / moz-extension:// origins which we can’t fully enumerate. The bearer token is the actual gate; anyone on localhost would still need the token to capture.

Structs§

AutofillPackage
The application package the user prepared from a tailored version: contact profile plus the resume rendered to bytes. Held in memory only (see module docs). prepared_at_ms is stamped server-side when the package is set.
AutofillProfile
Contact fields the extension maps onto an employer form. Field names are what the renderer sends (camelCase over IPC); everything defaults to empty so a sparse personal_info row still produces a usable package.
CaptureBridge
Hand-off between the HTTP handler and the webview. Tauri events are fire-and-forget: with no registered listener (app still booting, webview reloading) an emit “succeeds” and the capture evaporates, while the extension is told everything went fine. The handler consults this bridge instead: not ready means buffer, ready means emit. The frontend flips listener_ready by invoking drain_pending_captures after registering its listener; a page load in the main webview flips it back (see on_page_load in lib.rs).
CapturePayload
JSON payload from the browser extension.
CaptureServerState
Shared server state. The token is stored behind an RwLock so regeneration via the settings UI takes effect on the next request without restarting the server.
CapturedEvent
Event payload emitted to the frontend on a successful capture. Mirrors CapturePayload but with normalized text.

DEFAULT_CAPTURE_PORT
Default port the capture server binds to. Picked from the user range (1024-49151), unlikely-to-collide. Configurable via env TAILORRA_CAPTURE_PORT for users who already use 7341 (the pre-rename TAILOR_CAPTURE_PORT is still honored).

spawn_server
Spawn the capture server on the Tauri-managed async runtime. Returns immediately; failures (port in use, etc.) are logged via tracing-style eprintln so the app doesn’t crash if capture can’t start. The settings UI can probe the port with a GET on /healthz to surface server health.
