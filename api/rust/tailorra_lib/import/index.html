Expand description

Transactional workspace import.

The renderer talks to SQLite through tauri-plugin-sql, whose pooled connections cannot hold a transaction across invoke calls, so a wipe plus row-by-row restore from the WebView could destroy the target workspace on any mid-import failure. This module opens its own connection to the same database file and applies the whole import (wipe plus inserts) inside a single transaction: any error rolls back and leaves the workspace untouched.

Backup content is untrusted. INSERT column names come only from the whitelists below (derived from src-tauri/migrations/*.sql), unknown keys are ignored for forward compatibility, and every row id is regenerated (uuid v4) with child references remapped, so importing the same backup into two workspaces of one database cannot collide. Child rows whose parent is missing from the backup are dropped rather than failing the whole import.

import_workspace
Load a workspace backup (the JSON produced by exportActive in workspace-io.service.ts) into the given project of the given database file. Wipes the project’s working tables and restores the backup rows inside one transaction; on any error the transaction rolls back and the workspace is left exactly as it was.
