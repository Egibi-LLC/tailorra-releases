Engine-native resume PDF rendering.

Replaces the previous headless-Google-Chrome subprocess with the platform webview engine the app already embeds (WebView2 on Windows, WebKitGTK on Linux). A hidden helper webview loads the resume HTML and is printed to PDF in place, so PDF export needs no external browser and works wherever the app itself runs.

Flow: store the HTML under a one-time token, open a hidden WebviewWindow pointed at tailorpdf://localhost/<token> (served by serve below), wait for the page to finish loading, reach the native webview handle via with_webview, drive an engine-native print-to-PDF, and return the PDF as base64. The command [crate::render_resume_pdf_bytes] is the entry point.

PdfHtmlStore
Holds resume HTML keyed by a one-time token while a hidden export webview loads it. serve reads from here; render inserts before opening the webview and the cleanup guard removes the entry when the render ends.

PDF_SCHEME

Functions§

render
Render html to a PDF and return it base64-encoded. Runs the whole hidden-webview print flow; safe to call from a Tauri async command (it must not run on the main thread, since it blocks awaiting the print result).
serve
Serve the resume HTML for the hidden export webview. The token is the last path segment of the request URI; on Windows Tauri maps the custom scheme to http://tailorpdf.localhost/<token>, on Linux it stays tailorpdf://, but the path is /<token> either way.
